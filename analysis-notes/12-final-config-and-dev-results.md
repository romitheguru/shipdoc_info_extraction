## B3: column-role prompt, then the freeze
| Run (bake-off, 40 docs) | OVERALL | row F1 | docs exact | false fills | s/doc p50 | output tokens p50 |
|---|---|---|---|---|---|---|
| bake-off prompt, 8B 8-bit (note 09) | 89.35 | 87.1 | 72.5% | 0/15 | 16.4 | 409 |
| v1 column roles, 8B 8-bit, before the fixes | 82.0 | | | | | |
| v1 + fixes, 8B 8-bit | 90.27 | 92.2 | 67.5% | 1/15 | 30.6 | 757 |
| **v1 + fixes, 8B 4-bit (final)** | **90.99** | **92.5** | **70.0%** | **0/15** | **19.0** | 611 |
| v2 (role-keyed rows, compact JSON), 8B 8-bit | stopped at 16/40: ~38 s/doc, slower than v1 | | | | | |

**v1 prompt** (`shipdoc/prompts.py`): the model names each column's role (supplier/customer part number, PO,
quantity, other) from the seller's point of view before it writes the rows.

**Fixes found on the v1 errors** (all generic; none came from a fold-4 doc):
- **Lone customer column → supplier.** If no column was labelled supplier and exactly one was labelled customer,
  that column is the seller's. "Mfr Part #" was labelled customer on 3 docs.
- **Buyer-word swap.** If the supplier column's header has a buyer word (your, customer, cust, buyer, client) and the
  customer column's header doesn't, the two roles swap (dev_0032).
- **Integer-aware numbers.** European thousands like `2.500` in a quantity column are read as 2500.

**The freeze.** Prompt v2 was meant to cut output tokens (compact JSON) and stop invented values on scribbled dates
(the one 8-bit false fill, dev_0068). It ran slower than v1 (~38 s/doc), so it was stopped for time.
**8B 4-bit with v1 + fixes** was frozen instead. It is the best run measured, with 0 false fills, and it is 1.6× faster
than 8-bit. This reverses note 11's provisional 8-bit choice. The `PO` → `P0` misread that argued for 8-bit happens
with **both** widths under the v1 prompt (9 of 20 rows of dev_0033), so it no longer separates them. The v2 prompt is
kept for reference in `out/12_prompts_v2_not_used.py`.

**Column repairs as flags.** On 4-bit, the "repaired" flag fired 38 times and was right once (2.6% precision): the
repairs fix values rather than mark doubtful ones, so they are left out of the review-flags file
(`shipdoc/predict.py`). On the bake-off this raises value-level flag precision from 25.9% to 39.4%, with recall
unchanged at 90.3%.

- **0 column swaps on dev.** The column-role prompt and the repairs fix the bake-off's costliest failure.
- **Unseen (fold 4) 87.1 vs seen 94.3.** The gap is character reading on S/5/8- and O/0-dense part-number styles
  plus the `P0` invoice, not layout: no fold-4 doc has a column or header error.
- **Multi-page docs** are 32% fully correct (more rows, so more chances for one lookalike), but their row F1 (93.6) is near the average.

**Review flags on dev** (`eval.flags`): document level precision 68.8%, recall 88.0% (32 flagged, 22 of 25 wrong docs
caught); value level precision 28.0%, recall 82.1%. On fold 4 only: doc 61.5% / 80.0%, value 24.7% / 77.8%. All
value-level catches come from `not_in_ocr`; no ambiguous slash date occurred on dev.

**Test run:** 200 docs, schema-valid, 163 invoices and 37 waybills by the classifier. 2 invoices (test_0104,
test_0128) hit the 4,096-token output limit; test_0128 was cut off at its last row and came out empty. The invoice limit
was raised to 8,192 in `shipdoc/predict.py` and only those two docs were re-run; both then finished on their own at
about 4,100 tokens, with 30 rows each. No dev doc reached 4,096 tokens, so the dev numbers are unchanged. The
truncated outputs are kept in `runs/truncated_4096/`.

## Throughput (C3)
Over all 300 dev + test docs on the M5 Pro (24 GB): **20 s/doc median, 83 s p95, ~107 docs/hour**. The extractor
peaks at 8.1 GB. PaddleOCR-VL adds ~3–4 s/page (280 test pages in 1,120 s) at 2.3 GB, run as a separate pass.
Output length drives the time: about 20 generated tokens/s, and multi-page invoices produce up to ~4,100 tokens because
the v1 prompt copies every printed column. At the 10k docs/day assumed in note 10, one Mac handles ~2.5k/day; the GPU +
vLLM batching design remains the production recommendation.
