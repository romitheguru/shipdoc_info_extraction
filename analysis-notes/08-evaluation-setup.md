# 08: Evaluation setup: leave-supplier-out folds, bake-off set, harness

Code: `eval/` (`data.py`, `splits.py`, `evaluate.py`). The files `eval/folds.json` and `eval/bakeoff.json` are generated by `uv run python -m eval.splits`. The generation is deterministic, so rerunning gives identical files.

## Folds (train+dev pooled, 500 docs, 5 folds)
| fold | docs | invoice suppliers held out | carrier brands held out |
|---|---|---|---|
| 0 | 94 | Galdon, Kaston, Zerova | Quillon, Tidewater |
| 1 | 107 | Galdek, Heskeon, Jovova, Vexenta | Kestrel, Skybridge |
| 2 | 105 | Fenium, Talara, Tambova, Vexova | Bluefin, Vantrel |
| 3 | 90 | Jovon, Talitek, Vexaris | Meridian, Northwind |
| 4 | 104 | Brenara, Kastara, Kastitek, Lumex | Orbis, Silverline |

- **How folds are built:** greedy balance on doc counts, with the largest group first. Waybills are grouped by carrier brand, because they all share one template (note 01). That makes "unseen" weaker for waybills, and the report will say so.
- **Every fold holds out a mix of formats:**
  - at least one slash-date supplier (MM/DD or DD/MM)
  - a mix of column sets: with or without customer PN, with or without PO, and the `Our`/`Your` naming traps where they exist (Lumex, Kastitek, Zerova, Galdek, Jovova sit in different folds)
- **Rule of use:** anything *learned* for fold k (few-shot examples, thresholds, calibration) may only use docs outside fold k. Fold k's docs then form the `unseen` slice. The OVERALL for unseen suppliers is the mean over the 5 folds.
- **Known limit:** I have looked at every supplier while writing notes 01–07. Folds protect against data leakage, not human familiarity (see `PLAN.md`). The mitigation is that no rule may name a supplier, prefix or position.

## Bake-off set (step 2)
40 dev docs:
- **Coverage:** all 18 invoice suppliers plus 8 of the 10 carrier brands (one waybill each).
- **Enriched for hard slices:** 22 scanned, 13 multi-page, 10 with repeated parts, 6 illegible.

For a zero-shot method every supplier is unseen, so dev docs are a fair bake-off. Only methods that learn from labels (few-shot or calibration) need the folds.

## Harness
```
uv run python -m eval.evaluate --pred preds.json --set dev|train|all|bakeoff|fold:K [--out report.json]
```
- **What it prints:**
  - OVERALL, header accuracy, row P/R/F1, docs exact and false-fill rate
  - accuracy per header field and per row field
  - every slice (scanned, multi_page, repeated_parts, illegible, waybill), yes and no
- **Per-doc detail** (wrong header fields, row counts, false fills) goes to `--out` for error analysis.
- **Verified against `score.py`:**
  - Gold scores 100.00.
  - A perturbed dev file (dropped rows, nulled or filled header fields, 10 missing docs) gives **86.13** under both the harness and the official scorer, and every component number matches.
